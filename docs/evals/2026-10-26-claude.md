# Skill evals — 2026-10-26 — Claude Code

The first real measurement of every bundled skill against the bare model (hyvemind 0.2.0).

- **Agent:** Claude Code, `claude -p` with read-only tools (Read, Grep, Glob, git diff/status/log), identical in both arms.
- **Size:** 33 scenarios, 2 trials, 2 arms = 132 runs per eval. The eval was run twice.
- **Run 1** scored the `pr` scenarios wrongly. The check expected `hyvemind gate`, and the agent wrote `npx -y hyvemind@0.1.0 gate`. The pattern was fixed before run 2. For `pr`, only run 2 counts.
- Raw reports: [run 1](2026-10-26-claude-run1.json), [run 2](2026-10-26-claude-run2.json).

## What this says

- **`spec` (+0.5) and `pr` (+0.667) clearly earn their place.**
  - Without `spec`, the model writes acceptance criteria like "search should be fast" with no number.
  - Without `pr`, it lists the commands to open a PR and never gates or checks evidence first.
- **`plan` is marginal (+0.125).** Without it, the model usually writes exit checks without backticks, so `hyvemind run` cannot reliably extract the command. With it, still only about half the runs do it right, so the skill's wording needs to be stronger.
- **The other 10 skills are saturated *on these scenarios*.** Today's Claude Code already avoids those failures without help. Per `bee-skill-eval`, that is **not** a retirement:
  - the same verdict is needed on a second model (Codex and OpenCode were not installed for this run);
  - and the scenarios need to be harder, aimed at failures the model still makes in real sessions (the transcripts `bee-skill-miner` reads are the place to find them).
- **The `no-signal` verdict** was added in this release after a broken first attempt. A variadic `--allowedTools` flag swallowed the prompt, so every run failed in both arms. Under the old verdicts that would have read as "retire every skill".

## Run 3: `plan` after acting on the result

Runs 1–2 showed `plan` as marginal: with the skill, only about half the plans put exit
checks in backticks. The skill's rule was then made explicit (exactly
`Exit check: \`<command>\``, and why). The skill was re-measured with 3 trials ([raw](2026-10-26-claude-run3-plan.json)):

| Scenario | Bare | With skill |
|---|---:|---:|
| every-task-has-a-check | 0/3 | **3/3** |
| riskiest-first | 3/3 | 3/3 |

**`plan` is now earning (+0.50).** This is the loop hyvemind exists for: measure the
skill, change it, measure again. Here it improved a skill; elsewhere the same loop
would thin one.
