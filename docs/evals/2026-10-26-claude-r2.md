# Skill evals, round 2 — 2026-10-26 — Claude Code

This round re-measures the 12 skills that 0.3.0 changed or added (PR #5): the sharper rules
from the audit of ~40 real skills, plus the new `cleanup` and `release`. The other skills
were measured in [round 1](2026-10-26-claude.md) and have not changed since.

- **Agent:** Claude Code, `claude -p` with read-only tools, identical in both arms (as in round 1).
- **Size:** 3 trials, 2 arms, concurrency 2: 288 runs in run 1, then 78 and 36 in runs 2–3.
  Round 1 used 2 trials at concurrency 6.
- **Not directly comparable with round 1.** Every skill in this round had its text or its
  scenarios changed by 0.3.0 (new scenarios for the audit rules, and the `bee-` prefix
  dropped), and `cleanup` and `release` are new. Read lift within this round only.
- Raw reports: [run 1](2026-10-26-claude-r2-run1.json), [run 2](2026-10-26-claude-r2-run2.json), [run 3](2026-10-26-claude-r2-run3.json).

## What changed between runs

Every failed run's output tail was read before anything was changed.

- **`write-spec`, run 1: +0.111, and worse than bare on one scenario.** On
  `do-nothing-alternative` the skill arm failed 2/3 while bare passed 3/3. The skill said
  "score each on debt, foreclosure and reversibility" but gave no shape, so the model wrote
  "Why not chosen" lines and skipped reversibility and lock-in. The rule now asks for one line
  each for **Debt**, **Foreclosure** and **Reversibility** (one-way or two-way door). Run 2: +0.222.
- **`mine-skills`, run 1: +0.167.** On `aggregates-only` both arms described what the session
  held ("a pasted production deployment config and a customer's bug report") while saying they
  had left it out. Naming the contents still leaks them. The rule now says an example is its
  session id and step order, and never names what the session contained. Run 2: +0.333.
- **`evidence-rules`, runs 1–2: a scenario bug, `no-signal` on one scenario.**
  `docs-are-not-the-code` told the model to "end with exactly one line: GRADE: A | unverified"
  and then checked for `GRADE: unverified`, so obeying the prompt always failed. The prompt
  now lets the model choose the line. The rule was also made concrete: a grade taken from
  documents is recorded as `unverified`, with no letter. Run 3: 18/18 in both arms, saturated.

## Reading it

- **Earning: `open-pr`, `release`, `mine-skills`, `write-spec`.**
  - Without `open-pr`, the model gives push and PR commands with no gate or evidence step.
  - Without `release`, a backfilling migration ships as a patch.
  - Without `mine-skills`, the model runs the mining without asking first.
  - Without `write-spec`, the acceptance criteria fail its falsifiable-criteria check (3/3 bare runs), and "do nothing" is not weighed for reversibility.
- **Saturated is not retired** (see `skill-eval`). These scenarios no longer find a failure in
  today's Claude Code. A second model and harder scenarios from real sessions come before any
  retirement. That applies most to the rules added in 0.3.0 (`cleanup`, the `design-review`
  and `review-change` additions), which are new, so no real failure has been mined for them yet.
- **Caveat (as in round 1):** the bare arm can see user-level skills and global instructions.
  For a strict baseline, run from a clean profile.
